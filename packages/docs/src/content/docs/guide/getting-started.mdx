## Installation

```sh
npm install machina
# or
pnpm add machina
```

## Your first FSM

Import `createFsm` and pass it a config object. Here's a simple traffic light FSM:

```ts
import { createFsm } from "machina";

const light = createFsm({
    id: "traffic-light",
    initialState: "green",
    context: { tickCount: 0 },
    states: {
        green: {
            _onEnter({ ctx }) {
                ctx.tickCount = 0;
            },
            tick({ ctx }) {
                ctx.tickCount++;
            },
            timeout({ ctx }) {
                // Return a state name to transition, return nothing to stay put
                if (ctx.tickCount >= 5) {
                    return "yellow";
                }
            },
        },
        yellow: {
            timeout: "red",
        },
        red: {
            timeout: "green",
        },
    },
});
```

A few things to note:

- **`id`**: a label for debugging and events. It doesn't need to be unique, but it helps.
- **`initialState`**: the state the FSM boots into. `_onEnter` fires on every entry to a state (if present)
- **`context`**: a plain object scoped to this FSM instance, yours to mutate.
- **`states`**: a map of state names to handler maps. Each key (other than lifecycle hooks like `_onEnter` and `_onExit`) is an input name.
- **`onDispose`** (optional): a teardown hook beside `states`. `dispose()` calls it once with `{ ctx, emit }` so the FSM can release anything it acquired.

**Handlers** are functions that receive `{ ctx, inputName, defer, emit }`. Returning a valid state name triggers a transition. Returning `undefined` (or nothing) leaves the FSM in its current state.

<Aside type="tip">
    TypeScript infers the state names, the input names, and the handler signatures directly from
    your config, and you don't write manual type annotations. The compiler validates the transition
    targets in string shorthand. A typo like `timeout: "yellw"` is a type error.
</Aside>

## Interacting with the FSM

```ts
// Dispatch an input to the current state
light.handle("tick");
light.handle("tick");
light.handle("timeout"); // tickCount is 2, stays green

// Query current state
light.currentState(); // "green"

// Check if the current state can handle an input before committing
// (canHandle is primarily used internally by machina in hierarchical FSM scenarios)
if (light.canHandle("timeout")) {
    light.handle("timeout");
}

// Subscribe to lifecycle events
const sub = light.on("transitioned", ({ fromState, toState }) => {
    console.log(`${fromState} -> ${toState}`);
});

sub.off(); // unsubscribe when done

// Reset to initialState (fires _onExit / _onEnter)
light.reset();

// Tear it down: all subsequent calls become silent no-ops
light.dispose();
```

| Method                       | What it does                                                               |
| ---------------------------- | -------------------------------------------------------------------------- |
| `handle(inputName, ...args)` | Dispatch an input to the current state                                     |
| `canHandle(inputName)`       | True when the current state, or a mounted child FSM, can handle this input |
| `currentState()`             | Returns the current state name as a string                                 |
| `on(eventName, callback)`    | Subscribe to a lifecycle event. Returns `{ off() }`                        |
| `emit(eventName, data?)`     | Emit a custom event to subscribers                                         |
| `reset()`                    | Transition back to `initialState`                                          |
| `dispose()`                  | Permanently shut down the FSM. Runs `onDispose` first, when declared       |

## String shorthand

When a handler always transitions to the same state with no logic needed, use the string shorthand instead of a function:

```ts
// These are exactly equivalent
yellow: {
    timeout: "red",
}

yellow: {
    timeout() {
        return "red";
    },
}
```

TypeScript validates the shorthand: the target must be a key in your `states` config.
